What to fix first

Production query-log evidence separates admission queueing from the two query shapes that also need database work.

1 · Restore capacityProduction is capped at 2 replicas × 1 query slot. Reconcile the checked-in HPA maximum of 5 and test 3, 4, then 5 replicas.
2 · Fix log orderingAdd ts_bucket DESC before timestamp. One uncached production sample improved from 267 ms to 42 ms with identical rows.
3 · Use root spansMove trace_related to spans_root. One uncached sample improved from 149 ms to 47 ms and read 3.4× fewer bytes.
4 · Isolate workloadsReserve capacity for trace detail calls so long explorer scans cannot head-of-line block every telemetry API.
Measured cause: the eight slow APIs had 1.63–1.72 s HTTP p99 but only 72–374 ms ClickHouse p99 during the final high-load interval. Read the full remediation plan.
